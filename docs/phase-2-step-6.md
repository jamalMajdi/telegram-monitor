# المرحلة الثانية — الخطوة السادسة (أ + ب): التصنيف والقوالب والمراجعة

> النطاق المنفَّذ: تصنيف حتمي بالقواعد (10 تصنيفات بذرية)، قوالب جاهزة (7) مع حذف الحقول الغائبة،
> مُحدِّد قالب يطبّق أولوية O02، واجهتا مراجعة (قائمة + تفاصيل) بالتعديل اليدوي والحجب الإلزامي.
> **لم يُنفَّذ**: مسار النشر والوجهات والإرسال (المرحلة III)، وإدارة القوالب بواجهة (متاحة عبر API فقط).

## 1) قاعدة البيانات — `0013_classification_and_templates.sql`

| الكائن | المحتوى |
| --- | --- |
| `templates` | قالب لكل مستخدم: `name`, `description`, `is_builtin`, `enabled` + `unique (user_id, name)` و`unique (id, user_id)` |
| `template_fields` | حقول القالب: `position`, `field_key` (مفاتيح الاستخراج + `contact`), `label` (قابل للتعديل), `enabled` |
| `template_bindings` | ربط القالب بـ`source` أو `filter` أو `classification`؛ فهارس فريدة تمنع تعادل داخل المستوى |
| `message_classification` | صف تلقائي وصف يدوي منفصلان: `origin`, `classification_id`, `classification_name`, `confidence`, `ambiguous`, `evidence`, `classification_version` |
| `message_template_resolution` | القالب المختار وسببه (`resolved_by`) وتفاصيل التدقيق (`details`) |
| `user_config_state.default_template_id` | القالب الافتراضي (آخر درجة في الأولوية) |
| `telegram_sources.classified_count` | عدّاد الرسائل المصنَّفة (Q14) |

التصنيفات نفسها تستخدم `rule_sets` بنوع `classification` (Q8) — أي أنها قواعد وشروط ومصطلحات مثل الفلاتر تماماً.

## 2) التصنيف الحتمي (6-أ)

- **البذور العشرة** (§8): وظائف وفرص عمل (10)، طلبات المساعدة الدراسية (20)، واجبات واختبارات (30)،
  مشاريع جامعية (40)، عقارات (50)، بيع وشراء (60)، خدمات (70)، أخبار (80)، طلبات عامة (90)، **غير مصنف (100)**.
- «غير مصنف» يُبذر **بلا شروط** فلا يطابق أبداً؛ يُستخدم كثابت عرض فقط عند عدم مطابقة أي تصنيف — لا تصنيف مُخترع.
- **كسر التعادل** معلَن وحتمي: الأولوية (الأصغر أولاً) ← الاسم ← المعرّف، وهو نفس ترتيب محرّك التقييم.
- **الثقة**: `0.6 + 0.1 × (عدد الشروط المحققة، بحد أقصى 2)`، وتُخفَّض 0.1 عند وجود تصنيف منافس، ومحصورة في [0.35, 0.90].
  مع منافسين ⇒ `ambiguous = true` و`review_state = needs_review` مع بقاء الحالة `processed` (Q7).
- **التعديل اليدوي (O02)**: يُخزَّن صف `origin='manual'` مستقل بثقة 1.00، والعرض يفضّل اليدوي دائماً،
  والتصنيف التلقائي يبقى محفوظاً للتدقيق. إزالة التعديل تعيد التلقائي فوراً.

## 3) القوالب (6-ب)

- **البذور السبعة** (§7.2): طلب المساعدة الدراسية، الواجبات والاختبارات، المشاريع الجامعية، الوظائف، العقارات،
  البيع والشراء، الخدمات والطلبات العامة (وهو الافتراضي عند أول بذر).
- **حذف الحقول الغائبة**: يُبنى المنشور من حقول القالب المرتَّبة؛ كل حقل بلا قيمة يُحذف من النص ويُدرج في
  `missingFields` للشفافية — لا «غير متوفر» ولا قيمة افتراضية (§7.4).
- **وسيلة التواصل**: حقل `contact` يُبنى من **القيم المحجوبة فقط** (O03) وبلا تكرار؛ ولا يعبر أي رقم خام.
- **التخصيص (§7.3)**: تعديل تسمية الحقل، ترتيبه، تعطيله، أو استبدال قائمة الحقول بالكامل عبر `PATCH /templates/:id`
  (الحقول المعطّلة لا تظهر في المعاينة).
- **لا تخزين لنص مُعاد التركيب**: المعاينة تُبنى عند العرض من النتائج المخزَّنة، فيبقى الأصل سليماً (D04)
  وأي تعديل قالب ينعكس فوراً.

## 4) مُحدِّد القالب — أولوية O02 حرفياً

```
قالب مسار النشر (route) ← تخصيص المصدر ← الفلتر (أعلى أولوية مطابقة) ← التصنيف ← الافتراضي ← لا قالب
```

- `route` مُنفَّذ في العقد ومُختبَر، لكنه يُمرَّر `null` دائماً الآن (مسارات النشر للمرحلة III).
- لا تعادل داخل المستوى نفسه: قيود فريدة في المخطط تضمن قالباً واحداً لكل هدف.
- قالب معطّل أو محذوف يُتجاوَز تلقائياً ويُوثَّق السبب في `details.skipped` (تدقيق كامل للقرار).

## 5) خط المعالجة النهائي

```
هوية → فحص المحتوى → فلترة → حفظ المطابق + المطابقات (matched)
     → استخراج + تواصل + review_state (processed)
     → تصنيف حتمي → اختيار قالب → تخزين التصنيف وسبب اختيار القالب (processed)
     → [المرحلة III] قالب مسار النشر ← وجهات ← إرسال
```

كل مرحلة في معاملة مستقلة بعد تثبيت الهوية؛ فشل أي مرحلة ⇒ `failed` بلا إيقاف لنقطة الاستئناف (Q4).

## 6) واجهات المستخدم

| الصفحة | المحتوى |
| --- | --- |
| `/telegram/results` | قائمة المراجعة: تصفية بحالة المراجعة والتصنيف، ترقيم صفحات، التصنيف مع أصله (تلقائي/يدوي) والثقة، القالب وسبب اختياره، مؤشر انتهاء احتفاظ المحتوى |
| `/telegram/results/:identityId` | التفاصيل: التصنيف الفعّال + التلقائي، تعديل يدوي، تعليم كمراجَعة/إرجاع للمراجعة، معاينة القالب مع الحقول المحذوفة، الحقول بثقتها ومواضعها، فئات التواصل **محجوبة**، النص الأصلي **مقنَّع**، الفلاتر المطابقة |

- «حالة الالتقاط» أضافت بطاقة وعموداً لعدّاد الرسائل المصنَّفة.
- كل الطلبات مقيّدة بالمالك، وأي تعديل يُسجَّل في `audit_events`
  (`processing.review_updated`, `processing.classification_overridden`).

## 8) حدود معلنة

1. **إدارة القوالب** متاحة عبر API (`GET/PATCH /templates`, `PUT /templates/:id/bindings`, `POST /templates/default`)
   ولا صفحة لها بعد؛ الصفحات المطلوبة لهذه الخطوة (المراجعة + التفاصيل) منفَّذة.
2. **لا كشف للقيم الخام**: لا يوجد endpoint لعرض رقم تواصل غير محجوب. عند الحاجة للمرحلة III (إرسال فعلي)
   يُضاف مسار كشف صريح مع تدقيق، لا كجزء من هذه المرحلة.
3. **التصنيف قرائني بالكامل**: النصوص غير المطابقة لأي قاعدة تصبح «غير مصنف» بدل تخمين تصنيف.
4. **القوالب بذرية**: لا إنشاء قالب مخصّص من الصفر بعد (الاستبدال الجزئي/التعديل متاح)؛ يُضاف مع مسارات النشر.
5. **المعاينة نصية** (سطور «التسمية: القيمة») وليست قالب تيليجرام نهائياً؛ تنسيق المنشور للمرحلة III (§10.5).
6. **مؤجَّل بقرارات سابقة**: تعديل/حذف الرسائل (Q5)، منع النشر النهائي للمكرّر (Q6)، مسارات النشر والوجهات والإرسال.
7. لا اختبار حيّ: كل شيء على بوابة محاكاة وقاعدة PostgreSQL مدمجة.
