# تقرير المرحلة الثانية — الخطوة الأولى: بوابة اعتماد مكتبة MTProto

**الحالة:** منفّذ ومختبر داخل مساحة العمل. **لا اتصال حقيقي بـ Telegram** لعدم توفر بيانات اعتماد — لم يُدَّعَ أي نجاح اتصال.
**المكتبة:** `teleproto` **1.234.0** (MIT، طبقة مخطط 234).

## 1) المكتبة والإصدار وسبب الاختيار
- تم تثبيت `teleproto@1.234.0` (أحدث إصدار مستقر عند التنفيذ، ونُشر في 2026‑11‑22، MIT، Node ≥ 18، أنواع مضمّنة، تعمل مع ESM).
- سبب الاختيار: قرار صاحب المشروع + خصائص لازمة للمعمارية المعتمدة: سلسلة تحديثات مسمّاة مع `update.missed`/`catchUp` (D03)، أصناف أخطاء مستقلة مع `FloodWaitError.seconds` (O10/§11)، إمكانية تخزين الجلسة خارجياً عبر تمديد `StringSession` (لتشفيرها في القاعدة)، وحدود اتصال صريحة تمنع الحلقات.
- GramJS لم يُستخدم؛ الكود مكتوب على أنواع الإصدار المثبّت فقط.
- TDLib لم يُستخدم؛ بقي بديلاً يحققه عقد `gateway.ts` بتغيير تنفيذ واحد.

## 2) الملفات المنشأة/المعدلة
جديد: `src/modules/telegram/{config,gateway,teleprotoGateway,messageMapper,errors,sessionCipher,sessionStore,accountRepository,connectionManager,factory}.ts`، `src/cli/telegramSmoke.ts`، `src/db/migrations/0004_telegram_accounts_sessions.sql`، اختبارات `test/telegram-*.test.ts`, `test/telegram-fakes.ts`, `test/telegram-test-env.ts`، `docs/telegram-integration.md`.
معدل: `src/config/env.ts` (متغيرات TG + معالجة القيم الفارغة)، `test/harness.ts` (مفتاح تشفير اختباري)، `test/phase1.test.ts` (عدد الترحيلات 4)، `.env.example`، `package.json` (سكربت `telegram:smoke`).

## 3) إدارة الاتصالات والجلسات والتشفير
- عميل واحد لكل حساب، ملكية متحققة من القاعدة قبل أي اتصال، وحالة صريحة لكل حساب.
- إعادة اتصال محدودة (`TG_MAX_RECONNECT_ATTEMPTS`) بتأخير أسّي؛ لا إعادة على 4xx أو إبطال جلسة؛ FloodWait يوقف الحالة ويسجل `waitSeconds` دون انتظار داخل الطلب.
- الجلسة تُخزَّن مشفّرة AES‑256‑GCM في `telegram_sessions`، مع AAD مربوط بمعرّف الحساب، وحالة التحديثات داخل المغلّف، ومفتاح من البيئة مع دعم تدوير المفاتيح.
- لا طباعة أسرار: حجب في السجل + تدقيق يحتوي رموزاً تشغيلية فقط.

## 5) المشكلات التي ظهرت وكيف عولجت
1. **نداء `connect()` متكرر على نفس العميل** في اختبار إعادة المحاولة: أُعيد تصميم المحاكاة لتستهلك سيناريو المحاولات المشترك، فأصبح الاختبار يعكس سلوك المكتبة الحقيقي.
2. **تدوير المفاتيح:** الإصدار الأول ربط نسخة المفتاح بالترتيب في البيئة ففشل الفك بعد التدوير؛ أُضيف `TG_SESSION_ENC_KEY_VERSION` مع رفض مفتاح سابق عند النسخة 1.
3. **hang في اختبار المخزن:** الاستيراد الثابت لطبقة القاعدة قبل ضبط البيئة جعل المجمع يتصل بعنوان مؤقت؛ صُحّح بالاستيراد الديناميكي بعد تهيئة القاعدة في `before`.
4. **قيم `.env` الفارغة** (`TG_API_ID=`) أفشلت مخطط zod؛ أُضيف `optionalWhenEmpty` يعاملها كغير محددة.
5. **تثبيت الإصدار:** كان الاعتماد `^1.234.0`؛ ثُبّت بدقة `1.234.0` لتجنّب تغيير مخطط Telegram تلقائياً.
6. **تدقيق الاعتماديات:** `npm audit --omit=dev` لا يُظهر ثغرات في `teleproto` أو اعتمادياته، لكنه يُظهر تنبيهين سابقين من المرحلة الأولى (`zod`، `react-router`) مسجّلين في `docs/security.md`.
7. **تسريب جزئي في أداة الفحص:** كانت تطبع أول حرفين وآخر حرفين من مفتاح تشفير عشوائي؛ أُزيل التمويه واستُبدل بأمر التوليد فقط، فلا تُطبع أي قيمة سرية.
8. **طبقة locale في صورة PostgreSQL المضمّنة:** لا يوجد `en_US.UTF-8`؛ ثُبّت `C.utf8` في سكربت التطوير والاختبار (لا أثر على الإنتاج).

## 6) ما يحتاج تدخلاً منك
- **`TG_API_ID` و`TG_API_HASH`** من <https://my.telegram.org> (تطبيق باسم هذا النظام).
- **جلسة مصرّح بها** لهذا التطبيق: إما تسجيل دخول تفاعلي عبر `npm run telegram:smoke -- --login` (يرسل الرمز إلى حسابك)، أو `TG_LIVE_SESSION`.
- **رقم/حساب مخصص للمراقبة** (يُفضّل رقم غير حيوي) لأن تسجيل الدخول يجعل الجهاز ظاهراً في أجهزة تيليجرام النشطة.
- **مفتاح `TG_SESSION_ENC_KEY`**: يُولَّد وينفّذ في `.env` على الخادم؛ لا يُشارك في Git.
- تأكيد سياسة الاحتفاظ بيومين وقواعد الوصول للمصادر قبل الاختبار الحقيقي (D04/§19).

## 7) التقييم النهائي
**قبول تقني مشروط، لا اعتماد نهائي.** ما أُثبت: التكامل البنيوي مع Node/TypeScript، التشفير والعزل، منطق الحدود والأخطاء والمحاكاة الكاملة، وسلامة المرحلة الأولى.
ما لم يُثبت: الاتصال والمصادقة الحقيقيان، استقبال تحديثات فعلية، استعادة ما فات بعد انقطاع حقيقي، وسلوك FloodWait الحقيقي. لذلك **لا حاجة لدراسة TDLib الآن**؛ تُدرس فقط إذا فشلت البنود الحيّة أو ظهرت قيود جوهرية (مثل عدم استقرار الاستقبال عبر القنوات).

## 8) خطوات التشغيل والتحقق
```bash
cd telegram-monitor/apps/api
# 1) ضع TG_API_ID وTG_API_HASH وTG_SESSION_ENC_KEY في .env
npm run telegram:smoke                     # فحص التهيئة
npm run telegram:smoke -- --login --listen 30   # دخول تفاعلي واستماع 30 ثانية
npm run migrate                            # ترحيل 0004 (الحسابات والجلسات)
npm test                                   # 78 ناجحاً + 4 حيّة (تُفعّل بمتغيرات TG_LIVE_*)
# 2) الاختبارات الحيّة الآلية
TG_LIVE_API_ID=... TG_LIVE_API_HASH=... TG_LIVE_SESSION=... npm test
```

**نطاق متوقف عمداً:** لم يُبنَ محرك قراءة المصادر أو الفلترة أو التصنيف أو النشر، ولا واجهة ربط الحسابات. الخطوة التالية تنتظر مراجعتك.
