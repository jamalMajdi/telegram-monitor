## ١) الخلاصة في سطرين

**محرّك النظام (API + عامل الصندوق + اتصال MTProto) يحتاج عملية حيّة 24/7 — لا Serverless ولا
خطة تنام.** الحلّ المجاني الوحيد الباقي في 2026 الذي يعطي ذلك هو **آلة Oracle Cloud
Always Free**، وقاعدة البيانات **PostgreSQL على نفس الآلة** (لا قاعدة مُدارة مجانية)،
والواجهة **يخدمها الـAPI نفسه** على نفس المنفذ. كل ما تبقّى (Render/Koyeb/Fly/Neon)
إمّا ينام، أو أُغلق، أو تنفد ساعاته قبل نهاية الشهر.

فالقاعدة **لا تخمل أبداً** ⇒ تستهلك 720 ساعة عمل شهرياً، أي **تنفد الحصة في ~16 يوماً**
ثم تُعلَّق حتى الشهر التالي. أي أن «مجاني» هنا يعني **انقطاع نصف الشهر**.

## ٣) المبرر التقني مقابل متطلبات V1

1. **اتصال MTProto مستمر (TCP طويل العمر).** يحتاج مقبساً مفتوحاً دائماً من عملية حيّة.
   أي منصة «تُنيم» الحاوية تقتل الجلسة وتعيد الربط كل مرة (أو تفشل)، وServerless لا يصلح أصلاً.
   Oracle VM = مقبس مفتوح بلا وسيط.
2. **عامل الصندوق (Outbox) كل 30 ثانية + مسح تنبيهات كل 60 ثانية.** حلقة زمنية داخلية؛
   تحتاج عملية دائمة. على آلة واحدة مع الـAPI: صفر شبكة داخلية، وصفر تأخير على القاعدة.
3. **PostgreSQL بخصائص حقيقية.** المشروع يستخدم: enums، `jsonb`، CTE،
   `for update skip locked`، فهارس فريدة **جزئية**، تحويلات `interval`. هذه ليست SQLite
   ولا PostgREST؛ تحتاج PostgreSQL 15+ حقيقياً — و«على نفس الآلة» يمنحنا نسخاً احتياطياً كاملاً
   (`pg_dump`) بلا حدود تخزين (200GB) وبلا فيدورات خمول.
4. **البصمة الرمزية (RAM/CPU).** الـAPI + العامل + عميل MTProto ≈ **250–400MB**،
   PostgreSQL ≈ **150MB**، Caddy ≈ **30MB**. خطة أوراكل (2 OCPU/12GB بعد تخفيض يونيو 2026)
   تغطي هذا بأريحية عشرات الأضعاف. حتى e2-micro (1GB) على الحدّ.
5. **أصل واحد (Same-Origin) = صفر مشاكل جلسات.** الـAPI يخدم بناء الواجهة بنفسه
   (`WEB_DIST_DIR`) على منفذ واحد، فنُبقي `SESSION_COOKIE_SAMESITE=lax` و`COOKIE_SECURE=auto`.
   لو فصلنا الواجهة على نطاق آخر، صرنا مضطرين إلى `SameSite=None` + CORS + CSRF أدقّ —
   تعقيد بلا مقابل في هذه المرحلة.
6. **التشفير والتحديث.** Caddy يوفّر TLS تلقائياً (Let's Encrypt) خلف نطاق واحد،
   ونسخ احتياطي ليلي + ترحيلات مُشغَّلة عند الإقلاع (`systemd` واحد).

### الهيكلة المقترحة (خطة أ)

```
Oracle Cloud — Always Free ARM (2 OCPU / 12 GB / 200 GB)
└── Docker Compose
    ├── caddy        :80/:443  ← TLS تلقائي + ترويسات أمان (+ ضغط)
    ├── api          :4000 داخلي  ← Express + عامل الصندوق + MTProto + خادم الواجهة المبنية
    ├── postgres:17  :5432 داخلي  ← volume على القرص الدائم + healthcheck
    └── backup       pg_dump يومي → /backups (14 نسخة) → رفع إلى Oracle Object Storage (20GB مجاني)
```

- **المنافذ العامة المفتوحة: 80 و443 فقط** (SSH مقيّد بـIP الإداري عبر Security List).
- **الحماية من «استعادة الموارد الخاملة»:** سياسة أوراكل تعيد ملكية آلة Always Free إذا بقي
  CPU والشبكة والذاكرة (المئين 95) **تحت 20% لمدة 7 أيام**. تطبيقنا خفيف ⇒ نضيف مؤقتاً
  يومياً يرفع CPU لدقيقة (`nice`)، ونراقب من الخارج. خطر مُدار، لا خطر مُهمَل.
- **معمارية ARM64:** كل الاعتماديات JS صافية (scrypt من Node، `pg`، `teleproto`، `zod`) —
  لا ترجمة أصلية ⇒ صورة Docker واحدة تعمل على arm64 بلا تعقيد. (الملفات التي سأكتبها
  تُبنى لـ`linux/amd64` و`linux/arm64` معاً.)

### لماذا ليس Serverless للواجهة الآن؟
Cloudflare Pages مجاني وممتاز، لكنه يعني أصلين ⇒ كوكيز عبر نطاقات. نبقيه **خطة توسّع لاحقة**
(نقل الواجهة + تفعيل `SameSite=None` + `COOKIE_SECURE=true` + CORS) وليس خطوة أولى.

## ٤) ما أحتاجه منك (القائمة الفعلية)

### أ) حسابات تُنشأ (بترتيب الأولوية)
1. **Oracle Cloud Free Tier** — تسجيل ببطاقة للتحقق (خصم $1 مؤقت). اختر منطقة قريبة
   (Frankfurt/Singapore/Jeddah إن توفّرت) — **قدرة A1 تختلف بين المناطق**، وقد تظهر
   «out of host capacity» لساعات؛ إن ظهرت جرّب منطقة أخرى أو أعد المحاولة.
2. **GitHub Secrets** (داخل المستودع نفسه، لا في المحادثة): `DEPLOY_HOST` (IP العام)،
   `DEPLOY_USER`، `DEPLOY_SSH_KEY` (مفتاح خاص)، واختيارياً `GHCR_TOKEN` لدفع الصور.
3. **نطاق**: نطاقك الخاص (الأفضل، ~$8–10/سنة — ليس مجانياً) **أو** نطاق مجاني من DuckDNS
   (`yourname.duckdns.org`) يعمل مع Caddy بلا مشاكل. بدون نطاق لا يوجد HTTPS صحيح.

### ب) أسرار تُوضع **على الخادم فقط** (لا ترسلها لي في المحادثة)
`TG_API_ID` · `TG_API_HASH` · `TG_SESSION_ENC_KEY` · `TG_BOT_ENC_KEY` · كلمة مرور PostgreSQL
· بيانات SMTP (إن فعّلت البريد). سأولّد لك سكربتاً يولّد المفاتيح على الخادم نفسه
(`openssl rand -base64 32`) ويصبّها في `.env` بصلاحية `600`، ولا تمرّ عبر أي محادثة أو مستودع.

### ج) قرارات أحتاجها منك (٣ فقط)
1. **المسار:** Oracle (موصى) — أم Northflank إن تعذّر التسجيل ببطاقة؟
2. **النطاق:** تملك نطاقاً؟ أم نبدأ بـDuckDNS مجاني؟
3. **البريد:** نفعّل SMTP الآن (تحتاج مزوّداً: Brevo/Resend/Gmail App Password) أم نتركه
   معطَّلاً بأمان (رسائل `pending` بلا فقدان) ونفعّله لاحقاً؟

### د) إن أردت أن أنفّذ النشر بنفسي
أحتاج IP الخادم + مفتاح SSH (أو أضف مفتاحاً عاماً أولّده لك) — لكن **الأفضل أمنياً**
أن تُشغّل أنت سكربت التثبيت الذي سأكتبه (سطر واحد)، ويبقى المفتاح عندك.

## ٦) تحذيرات صريحة (لا أُخفيها عنك)

1. **«مجاني + دائم + لا ينام» يتقلّص في 2026:** Koyeb أغلق مجانيه، Fly ألغاه، Render ينام،
   وأوراكل **خفّضت** حصة ARM من 4/24 إلى **2/12** في يونيو 2026. الخطة تعمل اليوم ضمن 2/12،
   لكن اعتباراً من 2027 قد تحتاج آلة مدفوعة رخيصة (Hetzner ~€4–6/شهر) — الكود لا يتغيّر،
   فقط `DEPLOY_HOST`.
2. **أوراكل تطلب بطاقة** للتحقق، وقد يرفض التسجيل من بعض الدول/البطاقات. البديل الجاهز:
   Northflank Sandbox (مجاني، لا ينام) + قاعدة Supabase Free — سأكتب ملفات النشر بحيث
   ينتقل بين المسارين بتغيير متغيّرين فقط.
3. **الاستعادة التلقائية للموارد الخاملة** خطر حقيقي على تطبيق خفيف؛ عالجناه بمؤقت نبضة
   ومراقبة خارجية مجانية (UptimeRobot/BetterStack free).
4. **دخول تيليجرام يتم مرة واحدة من عنوان الخادم**: بعد النشر ستفتح الواجهة وتُدخل رقم الهاتف
   والرمز من **الخادم نفسه**. لا تحاول نسخ جلسة من جهازك إن أمكن (تجنّب `needs_reauth`).
5. **النسخ الاحتياطي ليس رفاهية:** القاعدة على نفس الآلة ⇒ نفاد القرص أو خطأ ترحيل يعني فقدان
   كل شيء. النسخة اليومية إلى Object Storage جزء من الخطة لا إضافة.
