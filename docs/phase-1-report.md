# تقرير المرحلة الأولى — تأسيس النظام والبنية الأساسية

**الحالة:** منفّذ ومختبر داخل مساحة العمل. لم تبدأ أي وظيفة تيليجرام أو معالجة أو نشر.
**المسار:** `telegram-monitor/` · **المرجع:** المتطلبات 1.0 + التصميم 1.2 (D01–D12، O01–O10).

## 1) ما نُفّذ
- هيكل مونوريبو (npm workspaces): `apps/api` (Node.js 20 + TypeScript + Express + pg) و`apps/web` (React 18 + Vite + Tailwind، عربية RTL).
- تهيئة بيئة صارمة بـ zod، رفض إعدادات خطرة في الإنتاج، وفصل القيم في `.env` غير المتعقّب.
- قاعدة بيانات PostgreSQL مع ثلاثة ترحيلات موثّقة، ومشغّل ترحيلات ببصمة SHA-256، و`npm run db:status`.
- نظام مستخدمين كامل: تسجيل، دخول، خروج، استعادة كلمة المرور، تغييرها، حذف الحساب، إدارة الجلسات.
- صلاحيات مستخدم/مدير، حماية آخر مدير، منع الإجراءات الذاتية، وعزل كامل بمعرّف الجلسة.
- جلسات ويب معتمة (بصمة فقط) + CSRF موثّق على الخادم + قفل محاولات + تحديد معدل + تدقيق.
- لوحة مستخدم (ملف/احتفاظ/كلمة مرور/جلسات) ولوحة مدير (إحصاءات، بحث المستخدمين، إيقاف/تفعيل، ترقية/تخفيض، إعدادات عامة، سجل تدقيق) — بلا أي محتوى رسائل (D07).

## 2) أبرز الملفات
```
apps/api/src/config/env.ts            تهيئة البيئة والتحقق
apps/api/src/app.ts                   تركيب Express: أمان، جلسة، CSRF، مسارات، أخطاء
apps/api/src/index.ts                 تشغيل الخادم والإيقاف الآمن
apps/api/src/db/pool.ts               مجمع الاتصالات + withTransaction
apps/api/src/db/migrate.ts            مشغّل الترحيلات والبصمات
apps/api/src/db/migrations/*.sql      مخطط الهوية والجلسات والتدقيق
apps/api/src/modules/auth/*           المنطق والمسارات والجلسات
apps/api/src/modules/users/routes.ts  الملف الشخصي والجلسات وحذف الحساب
apps/api/src/modules/admin/routes.ts  إدارة المستخدمين والإعدادات والتدقيق
apps/api/src/modules/settings/routes.ts إعدادات المستخدم
apps/api/test/*                       أداة اختبار + 34 اختباراً
apps/web/src/**                       الصفحات والمكونات وعميل API
scripts/dev-db.mjs                    PostgreSQL مضمّن للتطوير
docs/*                                التوثيق
```

## 3) الجداول
`users`, `user_settings`, `system_settings`, `user_sessions`, `password_reset_tokens`, `notification_outbox`, `audit_events`, `login_attempts`, `schema_migrations` — التفاصيل في `docs/database.md`.

## 4) ما يعمل فعلياً (تم التحقق منه بطلب حقيقي)
تسجيل حساب (بما فيه ترقية bootstrap لمدير)، دخول/خروج، جلسة حالية، تعديل الاسم، تغيير كلمة المرور مع إبطال الجلسات الأخرى، طلب استعادة وتعيين كلمة مرور جديدة برمز لمرة واحدة، عرض/إبطال الجلسات، إعدادات الاحتفاظ، إحصاءات المدير، قائمة المستخدمين، إيقاف/تفعيل حساب، ترقية/تخفيض الدور، تعديل إعدادات النظام، سجل التدقيق، حذف الحساب، وفحص صحة القاعدة.

## 5) الاختبارات
`npm test` → **35 اختباراً، 35 ناجحاً، 0 فاشل** على قاعدة PostgreSQL مؤقتة تُنشأ وتُحذف تلقائياً:
سلامة الصحة والترحيلات وإعادة تطبيقها، القيود والفرادة وحذف التتالي، التسجيل والتجزئة والتدقيق، رفض كلمة المرور الضعيفة، دخول خاطئ وقفل مؤقت، CSRF، إدارة الجلسات، منع الوصول الإداري، عزل جلسات الآخرين، إدارة المستخدمين وإيقافها، حماية آخر مدير، التدقيق دون أسرار، تغيير كلمة المرور، مسار الاستعادة الكامل، الإعدادات والقيم الافتراضية، تعطيل التسجيل، حذف الحساب، وتحديد المعدل.
بالإضافة إلى: بناء TypeScript للخادم والواجهة بنجاح، وتشغيل الواجهة والخادم وقاعدة البيانات وفحص `/api/v1/health` عبر وكيل Vite.

## 6) النواقص والقرارات المطلوبة
انظر `docs/limitations-phase-1.md`: مزوّد البريد، التحقق من البريد، سياسة كلمة المرور النهائية، نقل تحديد المعدل لمخزن مشترك قبل التوسع، RLS كتعزيز، ولا اختيار لمكتبة MTProto قبل بوابة المقارنة.

## 7) التشغيل محلياً
```bash
cd telegram-monitor && npm install
npm run dev:db                 # قاعدة تطوير مضمّنة (منفذ 55432)
cd apps/api && cp .env.example .env && npm run migrate && cd ../..
npm run dev:api & npm run dev:web
# الواجهة: http://localhost:5173  ·  API: http://localhost:4000
```
أول حساب بالبريد المطابق لـ `BOOTSTRAP_ADMIN_EMAIL` يصبح مديراً، أو `npm run create-admin -- email`.
