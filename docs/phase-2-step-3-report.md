# تقرير المرحلة الثانية — الخطوة الثالثة: إدارة مصادر تيليجرام

**التاريخ:** 2026‑11‑24 · **الحالة:** منفّذة ومختبرة محلياً، **بانتظار المراجعة** (لم تبدأ الخطوة الرابعة).

## 1) ما نُفِّذ

إدارة كاملة لمصادر المراقبة (قنوات ومجموعات) لكل مستخدم، بحيث يكون كل مصدر **مربوطاً بحساب تيليجرام واحد يملكه
المستخدم نفسه**، وكل عملية تمر عبر طبقة البوابة وعميل الحساب المتصل (لا اتصال ثانٍ، ولا قراءة بجلسة غيره).

- **الخلفية:** ترحيل `0006`، مستودع مصادر، خدمة مصادر، مسارات HTTP، عقد بوابة جديد (`listAvailableSources`
  و`resolveSource`)، وتوصيل في `runtime`/`app`. لا تغيير في D01–D12 ولا O01–O10.
- **الواجهة:** صفحة `/telegram/sources` (قائمة + إضافة بالمعرّف أو من محادثات الحساب + إيقاف/استئناف/تحقق/حذف +
  إعداد «تضمين رسائلي») وعنصر تنقّل جديد، بنفس مكوّنات التصميم الحالية.
- **الاختبارات:** ملف جديد `test/telegram-sources.test.ts` بـ**13 حالة** تغطي العزل والصلاحيات والحالات الحدّية
  وأعطال تيليجرام.
- **التوثيق:** `docs/telegram-integration.md` (§7.6)، `database.md` (§0006)، `security.md` (قسم المصادر)،
  `decisions-traceability.md` (قرارات S1–S8)، `limitations-phase-1.md` (البنود 15–18)، و`.env.example`.

### الجداول (ترحيل `0006`)

- `telegram_sources`: `id`, `user_id`→`users`, `account_id`→`telegram_accounts` (كلاهما cascade), `peer_type`
  (`channel|group`), `peer_id` (`bigint`), `title`, `username`, `status` (`active|paused`),
  `include_own_messages` (افتراضي `false`), `monitoring_started_at`, `last_verified_at`, `last_error_code`,
  `created_at`, `updated_at`. فهرس فريد `(user_id, peer_type, peer_id)`، وفهارس `user_id`/`account_id`، ومُشغّل
  `set_updated_at`.
- `telegram_source_periods`: `id`, `source_id` (cascade), `started_at`, `ended_at`, `reason`، مع فهرس فريد جزئي
  يضمن فترة مفتوحة واحدة لكل مصدر.
- لا جداول محتوى ولا رسائل ولا وسائط — خارج هذه الخطوة بقصد.

### المسارات (`/api/v1/telegram`، مصادقة + CSRF)

`GET /sources` · `GET /sources/:sourceId` · `GET /accounts/:accountId/sources/available?limit=` ·
`POST /sources` · `PATCH /sources/:sourceId` · `POST /sources/:sourceId/pause` · `/resume` · `/refresh` ·
`DELETE /sources/:sourceId`. حدود المعدل: 30/دقيقة للأفعال، 10/دقيقة لجلب المحادثات.

## 3) القرارات وأسبابها

| # | القرار | السبب |
|---|---|---|
| S1 | الهوية `(peer_type, peer_id)`، و`username` للعرض فقط | المعرّف الرقمي ثابت أما الاسم فيتغير (O01) |
| S2 | مصدر واحد لكل مستخدم لكل هوية، من أي حساب | O01: قراءة واحدة للمصدر؛ يمنع الازدواج بين حسابين لنفس المستخدم |
| S3 | رفض المحادثات القديمة (basic groups) والبوتات والمستخدمين صراحةً `400 unsupported_source_type` | التحويل الصامت يخلق مصدراً لا يمكن مراقبته فعلياً |
| S4 | `include_own_messages` افتراضي `false` لكل مصدر | §4.3: رسائل المستخدم لا تُعالج دون تفعيل صريح |
| S5 | تسجيل فترات التفعيل في جدول مستقل بنفس نمط فترات الحساب | يلزم لحساب نافذة القراءة لاحقاً (O09) بلا إعادة بناء |
| S6 | فصل الحساب يوقف مصادره (`account_unlinked`) ولا يحذفها | لا فقد بيانات بلا طلب المستخدم، ولا مصدر «نشط» على حساب مفصول |
| S7 | حذف المصدر يحذف صفّه وفتراته ويُبقي سجل التدقيق | منع بيانات يتيمة، مع الحفاظ على التدقيق (D07) |
| S8 | حد المصادر لكل حساب من البيئة (`TG_MAX_SOURCES_PER_ACCOUNT=25`) | D11/O08 |

**نقاط غامضة عُوملت بأقل افتراض ممكن (تحتاج إقراراً):**
1. **حد المصادر لكل حساب أم لكل مستخدم؟** اعتُمد «لكل حساب» (D11/O08) مع أن القيد الفريد للمصدر «لكل مستخدم»؛
   أي أن مستخدماً بحسابين قد يملك مصدراً واحداً فقط لكل قناة (O01)، بينما الحد يُحسب لكل حساب.
2. **رسائل المستخدم نفسه:** عُوملت كإعداد لكل مصدر (افتراضي الإيقاف) لا كإعداد عام — أقرب إلى §4.3.
3. **`refresh` عند فقدان الوصول:** قراري أن يُوقف المصدر تلقائياً (`paused` + `SOURCE_NOT_MEMBER`/`SOURCE_KICKED`)
   بدل إبقائه نشطاً بخطأ مسجّل؛ يتوافق مع «الفشل مغلقاً».
4. **حدود `getDialogs`:** قيمة `limit` الافتراضية للواجهة 100 محادثة، وتُمرَّر من الطلب بحد أقصى 500.

اختبارات `telegram-sources.test.ts` (13/13 ناجحة):

1. عرض المحادثات المتاحة ووسم «مضاف بالفعل».
2. إضافة بالاسم `@opps_group` ← هوية ثابتة، فترة مفتوحة، حدث تدقيق، بلا حقول حساسة.
3. رفض التكرار من الحساب نفسه ومن حساب آخر للمستخدم نفسه (صف واحد فقط في القاعدة).
4. رفض غير العضو (`409 source_not_accessible`)، النوع غير المدعوم (`400`)، المعرّف المجهول (`404`).
5. `FLOOD_WAIT` ← `429`، فشل الشبكة ← `503 telegram_unreachable`، حساب غير متصل ← `409 account_not_connected`
   بلا إضافة أي صف.
6. إيقاف/استئناف مع إغلاق وفتح الفترات، والاستئناف المتكرر لا يفتح فترة زائدة.
7. تعديل `includeOwnMessages`، الحذف، ثم إعادة الإضافة.
8. العزل: قائمة/قراءة/تعديل/إيقاف/استئناف/تحقق/حذف/إضافة لحساب الغريب/جلب محادثاته ← كلها 404، ولا يتغير
   شيء عند المالك.
9. فصل الحساب يوقف مصادره ويُغلق الفترة ويُبقيها ظاهرة.
10. `refresh` يحدّث العنوان، وفقدان الوصول يوقف المراقبة ويسجّل `SOURCE_KICKED`.
11. طلبات غير مصادقة ← 401، وتحقّق المدخلات (`identifier`+`peerId` معاً، `peerId` غير رقمي، uuid غير صالح) ← 400.
12. الحد الأقصى: 25 مصدراً تُقبل والسادس والعشرون `409 source_limit_reached`.
13. حد المعدل على عمليات المصادر يظهر فعلاً (`429 rate_limited`).

**أعطال واجهت التنفيذ وأُصلحت (للسجل):**
- `setStatus` فشل بـ«inconsistent types deduced for parameter $2» → صياغة `$2::telegram_source_status` مع `$2::text`
  في المقارنة (كان يظهر كخطأ 500 في الإيقاف).
- `coalesce(reason, $2)` في تحديث الفترات احتاج `$2::text`.
- معرّف uuid غير صالح كان يُرجع 500 → صار 400 عبر `parseBody`.
- المحاكاة الآن تطبّع المعرّف (`@name`, `t.me/name`) كما يفعل التنفيذ الحقيقي.
- اختبار عدد الترحيلات كان مضمّناً (5) → يُقرأ الآن من مجلد الترحيلات.

## 5) ما لم يُنفَّذ ويحتاج إقراراً

1. **لا اختبار حقيقي مع تيليجرام:** إضافة قناة فعلية من حساب مرتبط، وحل `@username` الحقيقي، وحدود `getDialogs`
   الفعلية، وأخطاء مثل `CHANNEL_PRIVATE` — كلها مغطاة بمحاكاة فقط، ولا تُقدَّم على أنها ناجحة حياً.
2. **لا فحص دوري للعضوية**: `refresh` يدوي فقط؛ الفحص التلقائي يحتاج عامل القراءة (مرحلة لاحقة).
3. **لا مزامنة/تخزين مؤقت لقائمة المحادثات** — تُجلب عند الطلب بحسب حدود المعدل.
4. **نقل حدود المعدل إلى مخزن مشترك** ما زال مطلوباً قبل الإنتاج (R6 قائم).
5. **حذف الحساب (revoke) مقابل حذف المصادر:** الحذف النهائي للحساب يُسقط مصادره بـcascade (سلوك قاعدة البيانات)،
   بينما «فصل» الحساب (`DELETE /accounts/:id` والحالة `revoked`) يوقفها ويُبقيها. يحتاج تأكيداً إن كان المطلوب
   الإبقاء حتى مع الحذف النهائي.
6. **لم يبدأ أي عمل على المرحلة الثالثة** (لا استقبال، لا توجيه، لا نشر).
