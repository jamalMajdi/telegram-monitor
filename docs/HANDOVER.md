# تسليم V1 — TG Monitor (مراقبة رسائل تيليجرام ومعالجتها ونشرها)

> حزمة كود مصدري كاملة، بلا أسرار وبلا `node_modules`. جُرِّبت على بيانات حقيقية:
> حساب تيليجرام MTProto حقيقي + بوت حقيقي + قناة نشر حقيقية.

## ١) ما تحتوي الحزمة

| المسار | المحتوى |
| --- | --- |
| `apps/api` | خدمة الـAPI + عامل الالتقاط + عامل النشر + مشغّل الاحتفاظ (عملية واحدة) |
| `apps/web` | واجهة عربية RTL (Vite + React) |
| `deploy/` | وحدات systemd، إعداد nginx + TLS، `api.env.example`، سكربتات النسخ/الاستعادة/الفحص/توليد المفاتيح |
| `docs/` | دليل التشغيل `runbook.md` · الأمان والحدود `production-readiness.md` · شرح المحرّك `engine-explained.md` · سجل القرارات `decisions-traceability.md` · تقرير التجربة الحيّة `live-demo-report.md` |
| `LOCAL-SETUP.md` | تشغيل محلي بخطوات (PostgreSQL مضمّن، بلا Docker) |

**غير مضمَّن قصداً:** `.env` (أسرار)، `node_modules`، `dist`، سجلات، أي جلسة تيليجرام أو رمز بوت.

## ٢) التشغيل السريع (تطوير محلي)

```bash
npm install
cd apps/api && cp .env.example .env      # ثم املأ TG_API_ID / TG_API_HASH / مفاتيح التشفير
cd ../.. && npm run dev:db               # PostgreSQL مضمّن على 55432 (طرفية أولى)
npm run migrate                          # 26 ترحيلاً
npm run dev:api                          # API + العاملان على 4000
npm run dev:web                          # الواجهة على 5173
```
أنشئ مديراً أولاً: `BOOTSTRAP_ADMIN_EMAIL=you@example.com` في `.env` ثم سجّل من `/register` بنفس البريد.

## ٣) النشر على الخادم (إنتاج)

اتبع `docs/runbook.md` بالترتيب: متطلبات ← مستخدم الخدمة ← قاعدة البيانات ← TLS وnginx ← النشر الأول ←
النسخ الاحتياطي ← المفاتيح ← الترقية ← المراقبة. نقاط لا تُتجاوَز:
- `NODE_ENV=production` يمنع `COOKIE_SECURE=false` و`AUTH_BEARER_FALLBACK=true` (يرفض الإقلاع).
- المنافذ المفتوحة: **80 و443 فقط**؛ الـAPI على `127.0.0.1:4000`.
- `healthcheck.sh` يعطي: `0` سليم · `1` خدمة متوقفة · `2` قاعدة بيانات · `3` عامل متأخر.

## حزمة P0 من التدقيق (منفَّذة — 2026-11)

المرجع: `docs/p0-implementation-report-2026-11.md` (التفاصيل والأدلة).

| البند | ما صار |
|---|---|
| U1/U5 تأكيدات الحذف | حوار تأكيد لحذف الوجهة، حذف المسار، وإعادة النشر (بالأثر: المعرّف، المسارات المرتبطة، السقف المتبقي من 3) |
| 1 البريد | SMTP حقيقي (TLS + STARTTLS، بلا مصادقة على قناة صريحة) + `SMTP_CA_PATH` لشهادة داخلية |
| 6 مستهلك الصندوق | يُسلّم فعلاً: لُقية، تأخير متزايد، `sent/failed`، وبريد معطَّل لا يحرق الصفوف |
| 7 الفشل المتكرر | تنبيه + بريد واحد + لافتة/شارة في الواجهة + `failureStreak` في الـAPI |

**ثلاثة أعطال إنتاجية اكتشفتها الاختبارات** (لم تكن في قائمة التدقيق): فهرس فريد جزئي كان
يُفشل **كل** إدراج في صندوق البريد (ومنه استعادة كلمة المرور) — أُصلح بالترحيل `0030`؛
حساب سلسلة الفشل كان يُطلق تنبيهاً مع وجود نجاحات أحدث؛ وقراءة ردود SMTP متعددة الأسطر كانت
تُسقط `STARTTLS`. التفاصيل في التقرير.

**تشغيلياً بعد الاستلام:** عيّن `SMTP_HOST` + `SMTP_FROM` + `APP_PUBLIC_URL` (وإلا يبقى البريد
معطَّلاً **بأمان**: رسائل `pending` بلا فقدان). بقية P1/P2 مؤجّلة إلى V2 بقرارك.

## ٨) بعد الاستلام — قائمة أمان فورية

1. أبطِل رمز بوت النشر من @BotFather إذا كان قد استُخدم في تجربة، ثم أدخل الرمز الجديد من الواجهة.
2. أنهِ أي جلسة تيليجرام تجريبية (أو احذف الحساب — يمسح جلسته المشفّرة).
3. غيّر كلمة مرور المدير التجريبية فوراً من `/account`.
4. ولّد مفاتيحك: `deploy/scripts/generate-secrets.sh` ثم انقل `.env` إلى `640 root:tgmon`.
5. تأكد أن `DEV_EXPOSE_RESET_TOKEN=false` و`AUTH_BEARER_FALLBACK=false` في `.env` الإنتاج.

## الفحص الآلي للواجهة (Render Smoke Test)

لا تحتاج متصفحاً للتحقق من سلامة الشاشات:

```bash

```

يشغّل React الحقيقي فوق jsdom باستجابات بنفس شكل الـAPI، ويفحص: رسم شاشة الفلاتر والتصنيفات،
عرض عدّاد الشروط، فتح المحرّر بجلب التفاصيل، الكتابة في الحقول، والحفظ وظهور القاعدة الجديدة، وبطاقة هوية المصدر والمرسل (رسم + معاينة + إيقاف فوري) — 24 فحصاً.

- إن أردت الفحص على القاعدة الحقيقية (قراءة + إنشاء فعلي):
  `SMOKE_LIVE_BASE=http://127.0.0.1:4000 SMOKE_COOKIE='tg_sid=…' npm --workspace @tg/web run smoke`

## هوية المصدر والمرسل (توقيع أسفل المنشور)

ميزة تجارية مكتملة: كل منشور يحمل أسفله **من أين جاء ومن كتبه**، مع تحكّم مرن بثلاث طبقات.

- **الافتراضي: مفعّلة (Opt-out)** لكل الرسائل وكل المسارات بلا أي إعداد. تظهر كذلك:
  `📣 المصدر: اسم القناة · @username` ثم `👤 المرسل: الاسم · @username` بعد فاصل رقيق `· · ·`.
- **العناصر (واجهة الإعدادات):** المصدر فقط / المرسل فقط / الاثنان، وإظهار @username (افتراضياً نعم)
  والمعرّف الرقمي (افتراضياً لا)، مع **معاينة حيّة** لشكل الأسطر. الحفظ فوري بلا زر.
- **لكل مسار على حدة (شاشة النشر):** «حسب الإعداد العام» / «بلا هوية» / تحديد صريح. إيقاف مسار
  **لا يمسّ** بقية المسارات ولا الإعداد العام.
- **الالتقاط:** من تحديث MTProto نفسه (`fromId` + كيانات التحديث + `postAuthor`) **بلا أي طلب شبكة إضافي**،
  ويُحفظ على `message_identity` وقت الاستقبال.
- **الأمان:** كل قيمة تُهرَّب، والأسماء/العناوين تمرّ على حاجب جهات الاتصال، و@username لا يُقبل إلا بنمط
  تيليجرام الصارم، والمعرّف أرقام فقط (لا روابط مخترعة). لا نصوص رسائل ولا بيانات تواصل في السجلات.
- **الحمايات القائمة لم تُكسر:** الهوية لا تُنقذ منشوراً فارغاً، وتُحتسب ضمن سقف 4096، ولا تُرسل وحدها.

الدليل: `apps/api/src/modules/publishing/attribution.ts` + الترحيل `0028_source_attribution.sql`،
والتفصيل التشغيلي: `docs/runbook.md §16` وبلا أكواد: `docs/ops-summary.md §10`.

**بوابات الجودة على هذه الحزمة:** `apps/api` **569** اختباراً ناجحاً بلا فشل (263 وحدة + 302 تكامل: منها 49 لميزة الإسناد وإصلاح التقاط المرسل
و28 جديدة لتدقيق ما قبل التسليم)،
`apps/web` بناء + tsc نظيف + `smoke:web` 24/24، وفحص حيّ على `:4000` للإعدادات ولتجاوز المسار وللسياق الكامل
من قاعدة البيانات الحقيقية.


## تدقيق ما قبل التسليم (الاستقرار + سلامة البيانات)

الملف الكامل: `docs/pre-handover-audit-2026-11.md`. الخلاصة: **خمس مشاكل حقيقية أُصلحت**،
وثلاثة محاور تحقّقت سليمة.

| المشكلة | الأثر قبل الإصلاح | الحالة |
|---|---|---|
| انقطاع MTProto صامت | الواجهة تقول «متصل» والحساب مقطوع (فقدان التقاط صامت)، ونفاد المحاولات يتركه ميتاً | نبضة حياة + استعادة تلقائية + محاولة بطيئة |
| رسالة تحمل `NUL` | **توقف التقاط الحساب كله** بلا نهاية (رسالة سامّة) | تنقية عند الحدّ |
| عميل ربط مهجور | اتصال MTProto حيّ للأبد لكل محاولة متروكة | منظّف كل دقيقة |
| لُقية منتهية | **نشر مكرر** في قناة العميل بعد سقوط العامل | المجهول لا يُعاد تلقائياً (`uncertain`) |
| 135 مستخدماً وهمياً | إقلاع يحاول 80 حساباً ويفشل 79 | نُظّفت (نسخة CSV محفوظة) |

**تحقّق سليم ولم يُمسّ:** سلوك الطابور عند فشل الوجهة (حجب/حذف/شبكة)، منع النشر المزدوج
(ثلاثة قيود بنيوية + اختبار تزامن)، ولا تسرّب ذاكرة في تشغيل مستمر 4 دقائق.

**اختبارات جديدة (28):** `telegram-liveness` (7)، `poison-message` (7)،
`telegram-login-sweeper` (6)، `lease-recovery` (3)، `publish-destination-failures` (5).

**المرحلة 3 (مراجعة):** 19 ملاحظة مصنّفة (U1–U9 تجربة مستخدم، 1–19 نظم/أمن/إعدادات)
مع ترتيب P0/P1/P2. **حزمة P0 اعتُمدت ونُفِّذت** (انظر «حزمة P0» أعلاه)؛
P1/P2 مؤجّلة إلى V2 بقرار صاحب المنتج.

## إصلاح «سطر المرسل لا يظهر» (2026-11-26)

شوهد منشور حقيقي يحمل سطر المصدر فقط. الفحص أثبت أن `sender_id` محفوظ لكن الاسم و@username = `null`،
والسبب أن تحديثات تيليجرام تحمل معرّف المرسل وحده بلا كائنات المستخدمين.

- **الحل:** `senderResolver.ts` — كاش محلي ⇒ `getEntity` ⇒ (عند الحاجة) جلب الرسالة نفسها بنوع نظير
  صريح ثم إعادة القراءة. مهلة 3 ثوانٍ، وصفر طلبات للمرسل المعروف، وأي فشل لا يُسقط الالتقاط.
- **إصلاح ذاتي:** الصفوف القديمة الناقصة تُكمَّل حين يُعرف المرسل لاحقاً (نفس المستخدم والمصدر فقط).
- **تحقّق حيّ منفَّذ:** استُخرج الاسم و@username فعلياً للرسالتين 19 و20 على مصدر «ارسال رسائل»
  (`Jemo09 / Jamal Majdi` و`D_F_student / الدكتور`)، وأُكمل الصفّان، وأصبح `renderAttribution`
  يُرجع سطرَي المصدر والمرسل في سياق التسليم الحقيقي.
- **درس:** تمرير رقم المجموعة مجرّداً يُفسَّر كمستخدم في المكتبة؛ لا بد من `PeerChat/PeerChannel` صريح.
- التفصيل: `docs/runbook.md §17`.
