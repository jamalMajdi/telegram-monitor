# تقرير إصلاح: انهيار شاشة الفلاتر (E-MWWD4Z41)

**التاريخ:** 25 نوفمبر 2026 · **الحالة:** ✅ مُصلَح ومُختبر · **الشاشات:** `/telegram/filters` و `/telegram/classifications`

---

## 1. ما رآه المستخدم

فتح `/telegram/filters` ⇒ شاشة الخطأ (Error Boundary) بالرمز `E-MWWD4Z41`، ولا شيء يُعرض.

## 2. السبب الجذري (Root Cause)

قائمة الفلاتر من الـAPI تُعيد **ملخّصاً** ولا تُعيد حقل `conditions` إطلاقاً:

```
GET /api/v1/telegram/filters  →  { filters: [ { id, name, description, enabled, priority,
                                                 scope, appliesTo, isBuiltin, version,
                                                 conditionCount, termCount, sourceIds, updatedAt } ] }
```

بينما `GET /api/v1/telegram/filters/:id` وحدها تُعيد `conditions` كاملة.

الصفحة كانت مكتوبة على أساس أن عنصر القائمة هو الكائن الكامل، فأول سطر عرض:

```ts
filter.conditions.map(...)   //  conditions === undefined  ⇒  TypeError
```

وهو خطأ يقع **داخل الرسم** (render) ⇒ يلتقطه Error Boundary ⇒ رمز `E-MWWD4Z41`.
نفس العلة في شاشة التصنيفات، حيث الملخّص أضيق أيضاً (لا `scope` ولا `termCount` ولا `sourceIds` ولا `updatedAt`).

**لماذا لم يكشفه المُصرِّف؟** لأن النوع `RuleDetail` (الذي يحتوي `conditions` إلزامية) كان مستخدماً لعناصر القائمة، فمرّ الخطأ من `tsc`، وظهر فقط عند التشغيل ببيانات حقيقية.

## 3. الإصلاح

| # | الملف | التغيير |
|---|-------|---------|
| 1 | `apps/web/src/api/client.ts` | نوع جديد **`RuleSummary`** يوثّق شكل الملخّص (بلا `conditions`)، والحقول الخاصة بالتصنيف اختيارية. `filters()` و `classifications()` تُعيد الآن `RuleSummary[]` — فأصبح المُصرِّف هو الحارس الأول. |
| 2 | `apps/web/src/pages/TelegramFiltersPage.tsx` | تعرض `conditionCount` من الملخّص، وتجلب **التفاصيل كسولاً** (`filter(id)`) لعرض شرائح الشروط، مع `?? []` في كل مسار. |
| 3 | `apps/web/src/pages/TelegramClassificationsPage.tsx` | نفس المعالجة، مع `termCount`/`updatedAt` اختيارية (`typeof x === 'number'` قبل العرض). |
| 4 | `apps/web/src/components/RuleEditor.tsx` | تحصين إضافي: `Array.isArray(rule.conditions)` و`Array.isArray(dictionaries)` قبل الاستخدام. |
| 5 | `apps/web/test/pages-smoke.tsx` | **اختبار دخان حقيقي** (تفصيله أدناه) يمنع تكرار الخطأ. |

مبدأ الإصلاح: **لا يُفترض وجود حقل لم يوثّقه الخادم.** الملخّص للعرض السريع، والتفصيل يُجلب عند الحاجة فقط (فتح المحرّر أو عرض الشرائح).

## 4. كيف اختُبر (بلا متصفح في بيئة التطوير)

بيئة العمل هنا لا تحتوي Chromium/Playwright (غير قابل للتثبيت) ⇒ لا يمكن التقاط صورة شاشة حقيقية. لذلك استُبدل بالاختبار التالي، وهو أقوى من لقطة بصرية لأنه **آلي وقابل للتكرار**:

`npm run smoke:web` (أو `npm --workspace @tg/web run smoke`) — يشغّل **React الحقيقي** فوق **jsdom** مع استبدال `fetch` باستجابات لها **نفس شكل** استجابات الإنتاج (ملخّص بلا `conditions`، وتفصيل يحتويها). 16 فحصاً:

1. شاشة الفلاتر تُرسم بلا انهيار.
2. اسم الفلتر يظهر من الملخّص.
3. عدّاد الشروط يظهر («3 شرط»).
4. شرائح الشروط تُعرض من التفاصيل الكسولة.
5. شريحة القاموس للشرط المنفيّ تظهر.
6. شاشة التصنيفات تُرسم بلا انهيار.
7. التصنيف الموحّد «خدمات طلابية» يظهر.
8. شارة «مبذور» تظهر.
9. شرائح شروط التصنيف تظهر.
10. زر «تعديل» موجود وقابل للنقر.
11. المحرّر يفتح بلا انهيار (يجلب التفاصيل بـ`id`).
12. المحرّر يعرض قسم الشروط المملوءة.
13. حقول المحرّر تقبل الكتابة (تحكّم React حقيقي).
14. الحفظ من الواجهة ينجح ويظهر تأكيده.
15. القاعدة الجديدة تظهر في القائمة بعد الحفظ.
16. بيانات الـAPI استُدعيت فعلاً (لا بيانات وهمية).

**إثبات أنّ الاختبار يكشف الخلل:** أُعيد الخلل القديم مؤقتاً (`filter.conditions.map`) ⇒ سقط الاختبار بالخطأ نفسه:

```
TypeError: Cannot read properties of undefined (reading 'length')
    at TelegramFiltersPage.tsx:177
```

ثم أُعيد الإصلاح ⇒ نجحت الفحوص الـ16.

### اختبار حيّ على القاعدة الحقيقية (وضع `SMOKE_LIVE_*`)

شُغِّلت نفس الصفحات مقابل API الحقيقي (قراءة + إنشاء)، فظهرت القوائم الفعلية (9 فلاتر، 7 تصنيفات) بنصوصها العربية وتواريخها:

```bash
SMOKE_LIVE_BASE=http://127.0.0.1:4000 SMOKE_COOKIE='tg_sid=…' npm --workspace @tg/web run smoke
```

- أُنشئ **فلتر تجريبي** من الواجهة نفسها (كتابة الاسم + المصطلح ثم «حفظ») ⇒ `201` ثم ظهر في القائمة فوراً.
- لوحظ `403` أول مرة ثم `201` بعد تجديد رمز CSRF تلقائياً — هذا سلوك العميل المقصود، لا خطأ.
- حُذفت كل الفلاتر التجريبية بعده (`204`)، فعادت القاعدة إلى نظافتها: 8 فلاتر.
